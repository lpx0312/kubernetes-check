# 实施阶段一：接口重构与多格式支持

本计划旨在增强工具的扩展性，使其支持多种输出格式（JSON/YAML），便于自动化集成。

## 1. 统一数据模型
- 在 `pkg/common` 或 `pkg/types` 中定义通用的检查结果结构体 `CheckResult`。
- 结构体应包含：`ResourceName`, `Namespace`, `Status`, `Message`, `Timestamp`, `RawData` (interface{})。

## 2. 重构 Output 模块
- 改造 `pkg/output` 包，定义 `Printer` 接口。
- 实现多种 Printer：
    - `TablePrinter`: 现有的表格输出（保持不变，作为默认）。
    - `JSONPrinter`: 序列化结果为 JSON 字符串。
    - `YAMLPrinter`: 序列化结果为 YAML 字符串。

## 3. 改造业务逻辑层
- 修改 `pkg/pod` 和 `pkg/node` 的检查方法，使其返回 `[]CheckResult` 而不是直接打印或返回特定结构体。
- 确保 CLI 层（`cmd/`）负责调用 Printer 进行展示，业务层只负责返回数据。

## 4. CLI 参数增强
- 在 `root` 命令或各子命令中增加全局 flag: `--output` 或 `-o`，支持 `table` (默认), `json`, `yaml`。

## 验证计划
- 运行 `go run ./cmd/pod-monitor pod -o json`，验证输出是否为合法 JSON。
- 运行原有测试 `go test ./test/integration/...` 确保表格输出未受破坏。
